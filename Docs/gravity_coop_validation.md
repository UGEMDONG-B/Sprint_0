# 1차 프로토타입 검증 기록

검증 환경: Unity 6000.3.10f1 / Windows / NGO 2.13.2 / Input System 1.18.0.

## 확인한 결과

| 항목 | 결과와 방법 |
|---|---|
| C# 컴파일 / Windows 개발 빌드 | 성공. 실제 Unity BuildPipeline 사용 |
| Missing Script / Reference | 생성 씬 261개 컴포넌트 검사 통과. 필수 플레이어·체크포인트·출구·상자·압력판·위험 참조 검사 통과 |
| 4방향 중력 | 아래·위·왼쪽·오른쪽 전부 실제 PhysX 낙하 확인 |
| 착지·이동·점프 | 네 방향 모두 원격 클라이언트 입력 RPC로 확인 |
| 물리 오브젝트 | 상자 네 방향 낙하 및 운반·내려놓기 확인 |
| 쿨타임 | 즉시 연속 변경 요청 거절 확인 |
| 역할 권한 | 내부 플레이어의 중력 변경, 조작자의 상자 집기 요청 거절 확인 |
| 사망·리스폰·리셋 | 현재 구간 복원과 중력·물체·장치 상태 초기화 확인 |
| 퍼즐 1 | 천장 이동 후 직접 출구 진입 성공 |
| 퍼즐 2 | 상자 운반 → 천장 압력판 → 상자 우회 → 출구 성공 |
| 퍼즐 3 | 위쪽부터 적용하면 선반에 막힘 확인. 오른쪽·위·왼쪽·위 경로로 성공 |
| 퍼즐 4 | 레이저 OFF 구간에 중력 변경하여 성공 |
| 퍼즐 5 | 두 상자 배치 → 레이저 통과 → 두 압력판 → 레버 → 출구 성공 |
| 2인 동기화 | 별도 호스트/클라이언트 프로세스에서 5개 퍼즐 연속 완료. 호스트 299개 검사 PASS, 클라이언트 최종 구간·문 상태 PASS |
| 카메라 배치 | 저장 씬을 GPU RenderTexture로 렌더링해 전체 관찰 / 캐릭터 주변 3인칭 시야를 확인 |

초기 시스템 테스트의 서버 위치/구간 설정은 테스트 준비에만 사용했다. 5개 퍼즐 풀이 중 플레이어는 원격 클라이언트의 실제 이동·상호작용 RPC로 조작했으며, 완료 상태를 강제로 설정하지 않았다.

## 검증 중 수정 / 확인한 사항

- 출구 주변 벽이 천장에서 접근하는 경로를 막던 배치를 정리했다.
- 출구를 뒤쪽 깊이 구간으로 좁혀 중력 조작만으로는 출구에 들어갈 수 없게 했다. 내부 플레이어의 W/S 이동이 필요하다.
- 퍼즐 2에서 상자를 밀면 압력판이 해제되는 정상 동작을 확인했다. 자동 풀이는 상자를 깊이 방향으로 우회하도록 수정했다.
- NGO의 구형 `RequireOwnership` 사용을 현재 패키지의 `InvokePermission`으로 변경했다.
- 연결 종료 후 씬 재시작 시 기존 NetworkManager를 제거하도록 정리했다.

## 아직 사람이 확인해야 하는 범위

- 서로 다른 인터넷 회선의 **Relay 코드 접속**, 실제 서비스 권한/설정 및 지연·패킷 손실 조건은 검증하지 않았다. 자동 테스트는 localhost 직접 접속이다.
- 두 사람이 역할을 바꿔 플레이했을 때의 재미, 멀미, 난이도, 설명 없이 조작을 이해하는지는 자동 검사로 판단할 수 없다.
- 캐릭터 위치는 호스트 권한이며 클라이언트 예측은 없다. 높은 지연에서는 조작 지연이 체감될 수 있다.
- 마우스 자유 회전, 음성 채팅, 로비·매치메이킹·세이브는 추가하지 않았다.
- 숨긴 batch-mode 플레이어 창의 스크린샷은 검게 캡처되어, 시각 검증은 저장 씬의 오프스크린 카메라 렌더를 사용했다. 실제 HUD 클릭·가독성은 Editor/일반 실행에서 최종 확인한다.

## 환경 특이사항

첫 Unity 실행에서 샌드박스의 사용자 캐시 쓰기 제한으로 시작이 실패했다. 허용된 Unity 실행으로 컴파일·빌드를 완료했다. 이 Windows 환경에서 Burst 캐시 DLL 로드가 차단되는 오류가 있어 배치 검증에는 `--burst-disable-compilation`을 사용했다. 게임 코드는 별도 Burst 작업에 의존하지 않는다. Editor에서 같은 DLL 오류가 재현되면 Jobs/Burst 메뉴의 Enable Compilation을 끄고 테스트한다.
