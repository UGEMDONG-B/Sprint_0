# 중력 협동 1차 프로토타입 실행 가이드

## 기준과 구성

`gravity_coop_implementation_spec.md`를 구현 기준으로, 아이디어 문서를 역할과 재미의 기준으로 사용했다. 기존 `SampleScene`, 4인 샘플 코드 및 패키지는 유지한다. 새 `GravityPrototype` 씬에서 기존 Input System, Netcode for GameObjects, Unity Transport, Multiplayer Services/Relay를 사용한다.

호스트가 중력 조작자, 접속자가 내부 플레이어다. 두 명이 로비에 모인 뒤 호스트가 시작 버튼을 누르면 시작하며 플레이 중 역할은 바뀌지 않는다. 역할을 바꾸려면 연결을 종료하고 상대방이 호스트가 된다.

## 혼자 테스트

Editor Play 또는 실행 파일 하나에서 **혼자 테스트 (좌우 분할)**을 누른다. 방 생성·로그인·인터넷 연결 없이 바로 시작한다. 왼쪽 절반은 중력 조작자 전체 시점, 오른쪽 절반은 내부 플레이어 1인칭 시점이다. 오른쪽 화면을 클릭하면 마우스 시선 조작이 시작된다.

- 화살표: 중력 변경
- WASD / 마우스: 내부 플레이어 이동 / 시선 회전
- Space / E / R: 점프 / 집기·내려놓기·레버 / 현재 퍼즐 리셋
- Esc → **테스트 종료 · 모드 선택**: 메인으로 돌아가 혼자 테스트 또는 멀티를 다시 선택한다. 진행 중 퍼즐 상태는 초기화된다.

혼자 테스트는 소켓을 열지 않는 OfflineTransport에서 동일한 권한·물리·퍼즐 로직을 실행한다. 왼쪽에만 자기 캐릭터가 보이고 오른쪽에서는 숨긴다. 두 카메라가 각자 3D 표식을 읽을 수 있게 방향을 맞춘다. 온라인 서비스 초기화는 멀티 버튼을 누를 때 시작한다.

## 멀티 실행

1. Unity 6000.3.10f1에서 `Assets/Scenes/GravityPrototype.unity`를 연다.
2. Editor와 `Builds/GravityPrototype/GravityPrototype.exe`, 또는 실행 파일 두 개를 실행한다.
3. 메인 화면에서 호스트는 **멀티 · 방 생성**, 참가자는 **멀티 · 방 참가**를 누른다.
4. 참가자는 기존 서버 검색 화면에서 공개 방을 선택해 **참가**한다. 기존 Multiplayer Services/Relay와 익명 인증을 그대로 사용한다.
5. 대기 로비에 2명이 모이면 호스트의 **시작** 버튼이 활성화된다. 시작 후 게임 화면으로 전환한다.
6. Esc로 기존 설정 화면을 열고 계속하거나 방을 나간다. 방을 나가면 씬을 복원해 메인 화면으로 돌아간다.

같은 PC에서 실행 파일 두 개를 쓸 때는 서로 다른 `-ugs-profile=gravityA`, `-ugs-profile=gravityB` 인수를 지정한다. Editor는 기존 방식대로 프로젝트 경로에 따른 별도 프로필을 사용한다. 기존 프로젝트의 UGS 서비스 설정과 인터넷 연결이 필요하다.

메인·서버 검색·로비·설정·서버 종료 화면의 원본은 `SampleScene`이다. 빌더는 이 UI와 `MultiplayerGameController`의 참조를 함께 복사하고, `GameHudScreen`은 비워 두고 게임 카메라가 전체 화면을 사용한다. 공통 화면을 수정한 뒤 프로토타입 씬을 다시 생성하면 반영된다. 중력 게임은 2인, 샘플은 기존 4인 설정을 유지하며 서로 다른 게임의 방은 검색 목록에서 구분한다. 일반 플레이용 IP·코드 접속 UI는 제거했고, 직접 접속은 개발용 자동 테스트에만 남겼다.
씬과 빌드 순서는 생성되어 있다. 수동 오브젝트 배치나 Inspector 참조 연결은 필요 없다. 씬을 기본 배치로 다시 만들려면 **Tools > Sprint 0 > Build Gravity Prototype**을 실행한다. 이 명령은 해당 프로토타입 씬의 수동 변경을 기본값으로 다시 생성하므로, 직접 조정한 씬을 보존하려면 먼저 별도로 저장한다.

## 조작

| 역할 | 조작 |
|---|---|
| 중력 조작자 | 방향키 |
| 내부 플레이어 | WASD: 카메라가 바라보는 방향 기준 이동, Space: 점프 |
| 내부 플레이어 | E: 표면까지 가장 가까운 상자 집기 또는 레버·회전 손잡이·고정 장치 조작. 들고 있으면 내려놓기가 우선 |
| 공통 | R: 현재 퍼즐 재시도(12번은 저장된 P 유지), Shift+R: 현재 퍼즐 완전 초기화 |

상자는 시선의 좌우 방향을 따라 운반하므로 옆걸음·뒷걸음에도 앞에 유지된다. 장애물에 닿으면 놓지 않고 멈추며, 길이 열리면 다시 따라온다. 장애물에 막힌 상자를 두고 멀리 이동해 중심 거리가 상호작용 거리 + 1(기본 3.2)을 넘으면 자동으로 놓는다. 벽 너머 집기는 허용하지 않는다.

청록색 작은 출구는 대부분 **방 뒤쪽**에 있다. 12번은 앞쪽 출구다. 중력만으로는 깊이 방향으로 이동하지 않으므로 내부 플레이어가 시점을 맞춰 깊이 방향으로 출구에 들어가야 한다. 주황색은 중력을 받는 상자, 노란색은 압력판, 보라색은 레버, 파란색은 문, 붉은색은 위험 구역이다. 활성 압력판과 레버는 녹색이 된다.

## 12개 퍼즐과 참고 풀이

정답 방향을 HUD에 표시하지 않는다. 다음 내용은 진행이 막혔을 때 테스트용으로 참고한다.

1. **벽으로 건너가기:** 뒤쪽 B 통로에서 위로 이동한다. 천장의 가림벽 앞에서 앞쪽 통로로 옮겨 벽을 지나고 출구로 간다. 출발 깊이와 전환 위치를 서로 알려준다.
2. **상자 주차:** 상자를 P 홈 아래에 준비하고 위로 보낸다. 내부 플레이어는 상자를 밀지 않도록 다른 깊이 통로로 빠진다. 오른쪽 중력에서도 받침 턱이 상자를 유지하는 동안 오른쪽 벽의 출구로 내려간다.
3. **두 갈래 배송:** 상자를 바닥의 하늘색 `A / LOAD` 구역 안에 놓는다. 내부 플레이어는 A 왼쪽의 스위치 아래로 빠진 뒤 준비 신호를 주고, 조작자는 위로 보낸다. 상자가 입구를 완전히 통과하면 근처 레버로 B를 연다. 오른쪽 중력으로 Q 압력판에 배송하고 아래쪽 출구로 이동한다. 문 안에 물체가 있으면 레버가 전환을 거절한다. `FRONT / REAR`는 카메라 방향과 무관한 방의 고정 앞뒤 이름이다.
4. **공중 환승:** 출발 턱에서 점프하며 오른쪽 중력으로 바꿔 넓은 벽에 착지한다. 다시 벽에서 점프한 뒤 위쪽 중력으로 바꿔 높은 받침 아래에 착지한다. 놓치면 바닥에서 다시 시도할 수 있고, 오른쪽 아래 위험 구역은 피한다.
5. **두 상자와 탈출로:** 하나는 P 홈 아래, 다른 하나는 A 입구 아래에 준비한다. 놓은 상자를 다시 밀지 않도록 깊이 방향으로 우회한다. 위로 보낸 뒤 B를 열고, 내부 플레이어가 LAUNCH 자리에서 점프하면 오른쪽으로 바꾼다. P를 유지하면서 Q에 배송한 상태로 출구 턱 아래로 이동한다.
6. **받고 다시 보내기 — 주고받기 실험:** A 아래에 상자를 놓고 위로 보낸다. 내부 플레이어도 A 입구로 이동해 천장에 도착한 뒤 왼쪽 스위치로 돌아가 B를 연다. 내부 플레이어가 뒤쪽 통로로 빠지면 조작자는 오른쪽으로 배송한다. Q가 눌리면 오른쪽 선반 뒤의 열린 통로로 내려가 출구로 간다.
7. **둘 다 준비됐어? — 함께 준비하기 실험:** 상자를 각각 P와 Q 표식 아래에 놓는다. 위쪽 중력으로 두 홈에 안착시킨 뒤 내부 플레이어는 뒤쪽 통로로 빠져 준비 신호를 준다. 오른쪽 중력에서도 두 상자는 턱에 남고, 플레이어는 앞쪽 가림벽을 우회해 출구로 간다.
8. **보관하고 길 열기 — 역할 교대 실험:** P 보관 홈과 A 입구를 준비하고 위로 보낸다. 내부 플레이어는 A를 지나 뒤쪽 천장 스위치로 이동해 B를 열어준다. 뒤쪽 탈출 통로에서 준비 신호를 주면 조작자가 오른쪽으로 바꾼다. P를 유지하면서 Q에 배송한 뒤 선반 뒤로 내려가 출구에 들어간다. 기존 5번의 점프 타이밍 대신 안전한 위치에서 다음 역할에 넘겨주는 과정을 비교한다.

9. **앞에서 받고 뒤로 보내기:** A(바닥)와 B(천장)의 두 창구 중 하나를 고른다. A는 내려간 상태에서 상자를 들고 창구로 이동한 뒤 뒤쪽으로 넘긴다. B는 먼저 위쪽 중력으로 상자와 사람이 천장에 도착한 뒤 인계한다. 상자를 뒤쪽에 내려놓고 위→오른쪽 중력으로 Q에 보낸다. 내부 플레이어는 오른쪽 벽을 따라 뒤쪽 출구로 이동한다. 하늘색 면과 테두리는 앞뒤를 나누는 투명 격벽이며 초록 테두리 A/B 창구에서만 상자를 넘길 수 있다.
10. **돌려서 이어주기:** 상자는 앞쪽, 내부 플레이어는 뒤쪽에서 시작한다. 위쪽 중력으로 내부 플레이어가 천장 손잡이 R1에 도착한다. R1을 돌리면 상자가 첫 통로로 올라온다. 내부 플레이어는 뒤쪽 천장을 따라 R2 손잡이로 이동해 두 번째 통로를 준비한다. 오른쪽으로 인계한 뒤 위→오른쪽 중력으로 Q에 배송한다. 통로 안에 물체가 있거나 새 벽이 물체와 겹치면 회전은 거절된다. 중간 선반은 실패한 상자를 받는다.
11. **하나를 남겨두고:** 첫 상자를 P 아래, 두 번째 상자를 뒤쪽 Q LOAD 구역에 준비한다. 내부 플레이어는 P 손잡이 아래로 이동하고 위쪽 중력을 요청한다. P에 상자가 멈추면 E로 고정한다. 내부 플레이어가 뒤쪽으로 빠진 뒤 오른쪽 중력으로 Q를 배송한다. P를 고정하지 않으면 첫 상자도 움직여 출구가 유지되지 않는다. 잠긴 상자는 집을 수 없으며, 손잡이에서 다시 E를 누르면 풀린다.
12. **배송팀:** 먼저 P 아래에 첫 상자를 준비하고 위로 보낸 뒤 고정한다. P가 인계문 A를 열며 잠금 성공 시 체크포인트가 저장된다. 아래쪽 중력으로 돌아와 두 번째 상자를 A 창구로 넘기고 뒤쪽 R1 LOAD 구역에 놓는다. 내부 플레이어는 A를 통해 앞쪽으로 돌아와 위쪽 중력으로 천장 손잡이에 접근한다. R1을 돌려 상자를 올리고 오른쪽으로 Q에 보낸다. 내부 플레이어는 앞쪽 출구로 내려간다. R 재시도는 P 잠금만 복원하고 두 번째 상자와 회전 통로는 초기화한다. Shift+R은 저장까지 지운다.

다른 협동 풀이도 허용한다. 방향이나 점프 횟수의 숨은 정답 체크는 없다. 압력판의 실제 점유와 출구 도달로 완료한다. 5번은 두 상자를 먼저 준비해 함께 보내는 풀이도 가능하도록 배치했다. 10번은 두 손잡이를 먼저 준비하는 계획도 허용하며, 앞뒤 서비스 통로를 활용하는 다른 운반 풀이를 모두 차단하지 않았다.

### 9~12번 기믹과 평가

- 회전 손잡이: 가까이에서 E. R1/R2 표식의 A/B 상태와 실제 ㄱ자 벽의 방향이 함께 바뀐다. 통로 내부 점유와 도착 벽의 겹침을 서버에서 검사한 뒤 즉시 90도 전환한다. 이동 애니메이션 중 물체를 밀어내지 않는다.
- 고정 장치: 상자가 P 테두리 안에 완전히 들어오고 멈춘 뒤 E. 들고 있는 상자는 고정할 수 없다. LOCKED가 보이면 중력을 바꿔도 유지된다. 다시 E로 해제할 수 있다.
- 인계: 앞뒤 격벽의 A/B 창구를 통해 직접 운반한다. 자동 순간이동이나 인계 제한 시간은 없다. 넓은 바닥과 천장에서 대화하며 준비할 수 있다.
- 비교 항목: 내부 플레이어가 A/B 창구를 선택했는지, 회전 준비와 배송 신호를 스스로 제안했는지, 잠금 확인이 의미 있는 판단인지 단순 심부름인지, 종합 방에서 대기 시간이 길어지는지 기록한다. 재미 검증은 네 방을 한 번에 플레이한 뒤 역할을 교대해 비교한다.

### 3번 위치 전달 실험 (2026-09-19)

두 역할이 공유하는 A/B/Q 명칭과 하늘색 A 배치 구역으로 "조금 더 왼쪽" 대신 "A 안에 놓았어"라고 전달할 수 있게 했다. A 투입구 폭은 2.4에서 4.8로 늘렸고, 바닥 표시는 3.2 × 4다. 표시 안에 상자를 놓으면 투입구와 벽에 여유가 있다. 바닥 표시는 충돌체 없는 페인트이며 자동 정렬이나 추가 정답 판정은 없다. 표식은 각 클라이언트의 카메라를 향하므로 내부 시점에서도 읽을 수 있다. 스위치는 넓어진 입구 옆의 막힌 선반 아래로 옮겼다.

이번 실험은 위치 전달 부담을 줄이는 데 집중한다. 내부 플레이어에게만 보이는 정답이나 새 경로 선택 규칙은 추가하지 않았다. 같은 두 사람이 같은 역할로 3번을 다시 플레이하고, 위치 수정 지시 횟수·앞뒤 혼동·내부 플레이어의 자발적 준비 신호를 비교한다. 전달 부담은 줄었지만 계획이 여전히 조작자에게 몰린다면 다음 실험에서 내부 플레이어가 경로를 판단하는 구간을 추가한다.

## 조절 지점

- `Gravity Game`: 중력 세기, 변경 대기시간, 리스폰 지연, 상호작용 거리, 운반 여유 높이(carryClearance), 카메라 회전 속도, 1인칭 눈높이(eyeHeight), 관찰 카메라 높이.
- `Runner`: 이동 속도, 점프 속도, 공중 조작 비율, 가속도, 시각 모델 회전 속도.
- 각 상자의 `Rigidbody`: 질량. `GravityBody`: 중력 영향 여부, 운반 가능 여부.
- `Assets/_Project/Materials/Gravity/*Friction.physicMaterial`: 마찰.
- 각 `Puzzle`의 `GravityPuzzle`: A/B 통로 문 연결, 출구의 레버 요구 여부, 위험 판정. 자식 Collider/Transform으로 판정 크기와 퍼즐 배치를 조정한다.

## 동기화와 임시 결정

- 물리와 상호작용 판정은 호스트만 계산한다. 클라이언트 Rigidbody는 kinematic이며 위치/회전은 서버 권한 NetworkTransform으로 받는다.
- 중력, 구간, 압력판, 레버, 문, 레이저, 운반 상태, 사망, 리셋, 완료는 서버 쓰기 NetworkVariable이다. 클라이언트는 입력 RPC만 보낸다. RPC 발신 역할·거리·가림·쿨타임을 서버에서 검사한다.
- 4방향은 월드 XY축, 방 깊이는 Z축이다. 공간은 3D이고 내부 플레이어는 표면의 두 축으로 움직인다.
- 작은 구간 12개를 한 씬에 배치하고 완료하면 다음 체크포인트로 이동한다. 현재 구간만 물리를 진행한다. 기존 1~5번, 협동 실험 6~8번, 새 기믹 9~12번이 순서대로 이어진다.
- 기본값은 중력 18, 쿨타임 0.5초, 이동 5, 점프 7, 공중 조작 0.45, 리스폰 0.8초다.
- 캐릭터는 캡슐 모양 Primitive와 구형 충돌체를 사용한다. 중력 회전 순간 충돌체가 벽에 끼는 일을 줄이기 위한 프로토타입 선택이다.
- 관찰자는 깊이를 읽을 수 있게 약간 기울어진 고정 전체 시점, 내부 플레이어는 마우스로 상하·좌우 회전하는 1인칭 시점이다. 게임 화면을 클릭해 시작하고 Esc로 기존 설정 화면을 연다. 자기 몸은 내부 플레이어 화면에서 숨겨지고 조작자에게는 계속 보인다. 휠 거리 조절은 제거했다. 중력이 바뀌면 눈높이와 카메라의 기준축도 부드럽게 회전한다. 감도·상하 각도 제한·눈높이는 Gravity Game Inspector에서 조정한다. 눈높이는 구형 충돌체 안쪽인 중심 위 0.25이며 최대 0.3으로 제한한다.
- 음성 채팅은 게임에 추가하지 않았다. 서로 대화할 수 있는 환경에서 평가한다.

## 자동 검증 실행

개발 빌드 전용 `-gravitySmoke` 옵션이 실제 두 프로세스의 입력 RPC와 PhysX를 사용한다. 일반 실행에는 테스트 입력이 개입하지 않는다.

```powershell
Start-Process ./Builds/GravityPrototype/GravityPrototype.exe -ArgumentList '-batchmode -nographics -gravityHost -gravitySmoke -logFile gravity-host-test.log' -WindowStyle Hidden
Start-Process ./Builds/GravityPrototype/GravityPrototype.exe -ArgumentList '-batchmode -nographics -gravityClient -gravitySmoke -logFile gravity-client-test.log' -WindowStyle Hidden
```

초기 시스템 검증에서는 테스트 배치를 위해 서버에서 위치/구간을 설정한다. 이후 12개 풀이에서는 클라이언트의 이동·집기·레버 RPC와 호스트의 중력 변경으로 진행한다. 호스트에 `-gravityCoopLabs`를 추가하면 6번부터 마지막까지 검사한다. `-gravityExpansion`은 9~12번과 새 기믹 안전 검사부터 시작한다. 따라서 자동 통과는 완성도나 두 사람의 재미를 증명하지 않는다. 서로 역할을 바꿔 플레이하고 조작자가 먼저 경로·상자·위험을 판단했는지, 내부 플레이어가 위치와 준비 상태를 전달했는지 함께 평가한다.

### 신규 협동 방 플레이테스트

6~8번은 기존 상자, 압력판, A/B 스위치와 연결 문, 출구, 고정 벽만 사용한다. 새 능력, 위험 구역, 제한 시간은 추가하지 않았다. 현재 게임은 내부 플레이어 한 명과 중력 조작자 한 명이므로, 8번의 도움 교대는 두 캐릭터의 교차 이동이 아니라 통로 개방과 중력 배송의 교대다.

각 방을 마치면 두 역할 모두에게 가장 재미있었던 순간과 기다리기만 했던 순간을 묻는다. 관찰자는 준비 신호가 자발적으로 나왔는지, 상대의 행동을 보고 계획을 바꿨는지, 한쪽이 모든 지시를 했는지 기록한다. 기존 3번과 비교하고 역할을 바꿔 재시도한다. 6번의 이동이 단순한 심부름인지, 7번의 준비가 반복 노동인지, 8번이 기존 5번과 충분히 다르게 느껴지는지도 확인한다. 재미가 확인된 방부터 확장한다.

## 장치 힌트 (2026-09-13)

- 조작자는 장치 위에 마우스를 올리면 하단에 이름, 작동 규칙, 현재 상태를 볼 수 있다. 열린 A/B 통로도 같은 위치에서 확인할 수 있다.
- 내부 플레이어는 화면에 보이는 가까운 장치의 설명을 본다. 벽 너머 장치는 제외하며, 일반 바닥보다 퍼즐 장치를 우선한다. 운반 중에는 내려놓기 안내가 우선한다.
- 상자의 E / CARRY, 압력판의 P·Q / WEIGHT, 출구의 P·Q / HOLD 표식으로 기능과 연결을 표시한다. 상세 설명은 한국어다.
- 압력판은 노랑=비어 있음, 초록=눌림이다. 조작자 HUD는 각 판의 이름과 상태, A/B 통로 상태를 표시한다.
- Inspector의 GravityHint에서 장치 설명을, GameHudScreen의 GravityHud / Hint Distance에서 근접 안내 거리를 조정한다. 별도 수동 설정은 필요 없다.
- 안내는 작동 규칙만 설명한다. 중력 방향 순서나 상자 운반 경로를 추가로 알려주지 않는다. 3D 이동과 기존 퍼즐 조건은 유지한다.


## 전체 화면 플레이 (2026-09-13)

사용자 요청에 따라 양쪽 역할의 상단 정보·버튼 패널과 하단 설명 패널을 제거했다. 앞 절의 마우스 검사/근접 HUD 안내는 더 이상 표시하지 않는다. 월드 내 장치 표식은 유지한다. 중력 조작은 방향키, 리셋은 R, 설정·방 나가기는 Esc를 사용한다. 내부 플레이어는 게임 화면 어디든 클릭하면 마우스 시점 조작을 시작한다.
